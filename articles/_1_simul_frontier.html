Testing frontier

Testing frontier on binary solved/failed is not fruitful; the task is too easy for frontier model. Instead, we ask model to produce top several choices with probabilities and compute loss. We expect model to prioritize promising direction of ‘research’. Thus, we can make metric a little more complex without asking model to actually do arithmetic - ask for top K samples and evaluate on order. ROC AUC?

Ask for top 3 options? With probabilities?

This will be a small approximation of ‘doing research’. In our case verifying guess is ‘cheap’, but we can imagine that exploring each option comes at some cost C - in this case, getting probabilities and thus prioritizing wrong will come at the variable cost.

We can use different loss functions.

Setup

Let’s create a dataset of 60 endgames, split it into batches of all divisor sizes and run same model with the same settings. The 60 samples were picked to be more likely to be complex - more valid choices, less prominent top option.

The goal is to test if larger set of ‘same’ tasks is more complex to the models.

One option to make it challenging for frontier is to ask model to produce top K answers and ask to estimate probability, and require some sort of ‘meta-auc’ or log loss.
